Abstract

Status and scope

Meta-Harness Language (MHL) is a declarative language for defining controlled AI-assisted automation. A program declares agents, prompts, tools, memory stores, protocol extensions, and executable pipelines. The runtime owns sequencing, branching, retries, timeouts, persistence, concurrency, verification, and termination; an agent is a replaceable participant within that harness.

This specification is intentionally ECMA-like: it separates lexical and syntactic grammar from runtime semantics, defines the standard callable surface, and uses normative terms. It is a self-contained reference, not a tutorial.

1. Conformance

A conforming implementation MUST parse valid source according to this specification, MUST reject malformed source, and MUST implement the observable semantics of expressions, statements, declarations, and standard-library operations. An implementation MAY provide additional extension kinds, CLI integrations, or host policies, but MUST NOT change the meaning of the core language in a conforming profile.

The reference implementation is the mhl command-line runtime. The current profile is versioned independently from this document and can be queried with mhl version. The profile is evolving; unsupported configuration is rejected rather than silently ignored where the runtime can validate it.

Conformance boundaryThe language core is deterministic for a given input and external-operation result. Agent responses, files, network services, clocks, and extension processes are host effects; their values are observable inputs to the program.

2. Terms and notation

Grammar productions use ::= for definition, square brackets for an optional item, braces for repetition, and quoted text for literal tokens. The notation T[] means an array whose elements have type T. A signature ending in → null returns no useful value; → never always raises.

3. Lexical grammar

Source files normally use the .mh extension. The lexer MUST ignore spaces, tabs, carriage returns, newlines, and comments beginning with // and continuing to the end of the line.

TokenFormSemantics
Identifier[A-Za-z_][A-Za-z0-9_]*Names declarations, variables, fields, methods, and enum variants. Keywords are recognized by position.
StringDouble quoted, with backslash escapesOne string value. A string is not re-tokenized when its content happens to be an operator.
Multiline string""" ... """String value with the delimiters removed and surrounding whitespace trimmed.
Number[0-9]+ or [0-9]+.[0-9]+A number represented by the runtime as a floating-point value. Scientific notation is not part of the grammar.
Duration[0-9]+(ms|s|m|h|d)A contextual duration literal, for example 250ms, 30s, 2h, or 7d. The numeric part is integral.
Operators== != < > <= >= + - * / % ! && || ?? +=Operator tokens. Multi-character operators take precedence over their prefixes.
Punctuation-> . ?. ?.[ ] ( ) { } : , .. ^ =Separates grammar constructs and forms access, calls, slices, lambdas, and assignment.
Malformed numeric textA digit run directly followed by letters that is not a duration, such as 10.0d, 1e5, or 5days, MUST be rejected as a malformed number.

4. Syntactic grammar

The following is a compact grammar. The complete behavior of each production is specified in the subsequent clauses.

program        ::= declaration*
declaration    ::= ["export"] (use | agent | prompt | memory | tool | extension
                    | pipeline | workflow | type | enum | test)
use            ::= "use" "{" use-item ("," use-item)* "}" "from" String
use-item       ::= Identifier ["as" Identifier]
type-alias     ::= "type" Identifier "=" type
type           ::= Identifier array-suffix* | object-shape array-suffix*
object-shape   ::= "{" [shape-field (","? shape-field)* ","?] "}"
shape-field    ::= Identifier ":" type
expression     ::= coalesce
coalesce       ::= or-expression ("??" or-expression)*
or-expression  ::= and-expression ("||" and-expression)*
and-expression ::= equality ("&&" equality)*
equality       ::= comparison (("==" | "!=") comparison)*
comparison     ::= additive (("<" | ">" | "<=" | ">=") additive)*
additive       ::= multiplicative (("+" | "-") multiplicative)*
multiplicative ::= unary (("*" | "/" | "%") unary)*
unary          ::= ["!" | "-"] postfix
postfix        ::= primary trailer*
trailer        ::= "." Identifier | "?." Identifier | "?." "[" expression "]"
                 | call | "[" expression "]" | slice
call           ::= "(" [argument ("," argument)*] ")"
argument       ::= [Identifier ":"] expression
slice          ::= "[" [slice-bound] ".." [slice-bound] "]"
slice-bound    ::= ["^"] expression
lambda         ::= "(" [parameter ("," parameter)*] ")" "->" (expression | block)
if-expression  ::= "if" "(" expression ")" expression "else" expression
match          ::= "match" expression "{" match-arm+ "}"
match-arm      ::= ("_" | expression) "->" expression
block          ::= "{" statement* "}"

A declaration body is a sequence of properties and/or declaration-specific members. Object fields may be separated by commas, line breaks, or both. MHL does not require semicolons.

5.2 Declared type expressions

Type annotations are accepted on pipeline inputs, prompt parameters, tool parameters, tool returns, and object-shape fields. The built-in vocabulary is any, string, number, bool, array, and object. The compatibility spellings int, integer, float, and boolean resolve to number or bool. Prompt parameters MAY use the pseudo-type prompt.

type Slug = string
type Issue = {code: string, severity: string}
type IssueList = Issue[]

tool Reports {
    add(slug: Slug, issues: IssueList): string[] -> issues.map((x) -> x.code)
}

An array suffix adds one nesting level: string[][]. An object shape requires the named fields and their types, but permits extra fields. Aliases are purely syntactic names, MAY reference other aliases, and MUST NOT be cyclic, duplicated, unknown, or shadow a reserved built-in name. A value of null is assignable to any declared type. Other values are checked by exact runtime kind; there is no implicit number/string conversion.

Duration boundaryDuration tokens are consumed by operations and configuration fields that explicitly expect a duration, including time arithmetic, retry delays, cache TTLs, wait/step/group timeouts, and HTTP or command timeouts. A duration is not a general-purpose declared value type in the current profile.

6. Expressions

6.1 Evaluation and precedence

Expressions are evaluated from lowest to highest precedence in this order:

?? → || → && → == != → < > <= >= → + - → * / % → unary ! - → member, optional member, call, index, and slice.

FormSemantics
Literal / identifierProduces the literal or resolves a value in the current scope. Unresolved identifiers raise.
a + bNumeric addition, string concatenation, or array concatenation. Other combinations raise.
a - b, a * b, a / b, a % bNumeric arithmetic. Division by zero raises.
a == b, a != bType-aware deep equality; arrays and objects are compared recursively and in order.
a < b etc.Numeric comparison. String ordering is provided by time.compare, not these operators.
!x, -xBoolean negation or numeric negation. The operand kind is checked.
a && b, a || bShort-circuit boolean conjunction/disjunction. Both operands MUST be boolean when evaluated.
a ?? bReturns a unless it is null; evaluates b only for null.

6.2 Access, indexing, calls, and interpolation

var title = record.title
var item = items[0]
var last = items[^1..]
var safe = record?.metadata?.owner ?? "unknown"
var dynamic = record?.[field_name]
var message = "${title}: ${items.size()} items"
var next = Transform(value: 3)

Plain member access requires an object field and raises when absent. Plain array indexing is zero-based and raises outside the array. Object indexing requires a string key. Slices use an inclusive lower bound and exclusive upper bound; omitted bounds mean the beginning or end, and ^n counts from the end. Slice results are new arrays.

Optional member access (?.name) and optional dynamic indexing (?.[expr]) yield null for null, non-object receivers, missing object fields, or out-of-range array indexes; the remainder of the trailer chain is skipped. Calls accept positional or named arguments. A named argument has the form name: expression.

String interpolation evaluates the expression between ${...} in the current environment. It is available in ordinary strings, multiline strings, prompt bodies, agent argument values, log paths, and memory paths. Values are formatted as strings, with structured values represented as JSON-like text.

6.3 Conditionals, lambdas, and match

The expression form if (condition) when_true else when_false evaluates exactly one branch. A lambda has the form (parameters) -> expression or (parameters) -> { statements }. Tool methods and lambdas bind positional parameters left-to-right; defaulted parameters MUST be trailing for these callables.

var even = values.filter((n) -> n % 2 == 0)
var label = if (ready) "ready" else "blocked"
var decision = match status {
    Status.Draft     -> "hold"
    Status.Published -> "ship"
    _                -> "skip"
}

match evaluates its subject once, tries arms top-to-bottom, and selects the first pattern deeply equal to the subject. The underscore is a wildcard. For an enum or boolean subject, a match without a wildcard MUST be exhaustive under static analysis. A match with no matching arm raises at runtime.

7. Statements

Statements occur in pipeline steps, tool method blocks, lambda blocks, and test descriptions. An inline statement is permitted where a braced block would otherwise occur.

StatementFormBehavior
Variablevar x = expressionCreates or rebinds a step-local value.
Constantconst x = expressionCreates a binding that cannot be the target of = or +=.
Assignmenttarget = expressionUpdates a variable, object field, or array element.
Add-assignmenttarget += expressionEquivalent to target = target + expression.
Conditionalif (condition) statement [else statement]Executes the selected body.
Whilewhile (condition) statementRepeats while true; the implementation caps interpreter iterations at 10,000.
For-infor (var item in array) statementEvaluates an array and visits each element in order.
Trytry { ... } catch (err) { ... } finally { ... }Catches raised errors and executes finally when present.
Returnreturn [expression]Exits the current tool method or callable block. In a step it returns from the step.
Breakbreak [expression]Stops the current pipeline run and, for a loop pipeline, stops further iterations. It is not a nearest-while/for exit.
Pausepause([expression])Suspends the run at this step for a human-in-the-loop hand-off — neither a failure nor a completion. The checkpoint is kept; mhl run --resume (or the server's run/resume) re-enters this step with any merged inputs. It is a control signal, so try/catch does not catch it, and it needs no checkpoint block.
Gotogoto StepNameTransfers to a named step. Legal only in a workflow.
Expressioncall(...) or any expressionEvaluates for its side effect or discards its value.

fail(...values) raises an error whose message is the formatted, space-joined values. A non-zero process exit code, an HTTP non-2xx response, and a failed assertion are values or test outcomes according to their APIs; they do not automatically become language raises unless documented otherwise.

8. Programs and modules

A program is a sequence of top-level declarations. There is no implicit namespace object. A declaration marked export is eligible for import by another file.

// shared.mh
export prompt Greeting(name: string) { "Hello, ${name}!" }
export tool Text {
    upper(value: string): string -> value.to_upper()
}

// main.mh
use {Greeting, Text as TextUtil} from "shared.mh"
pipeline Welcome {
    input name: string
    step Say {
        log(Greeting(name: name))
        log(TextUtil.upper("ready"))
    }
}

use imports an explicit list of exported names, optionally assigning a local alias. Imports are resolved transitively and flattened into the current program namespace; there is no namespace-qualified import syntax. Duplicate names, missing files, non-exported names, and alias collisions are static errors.

9. Declarations

The declaration keywords are agent, prompt, memory, tool, extension, pipeline, workflow, type, enum, and test. Names are unique within the flattened program namespace.

9.1 Type aliases and enumerations

type UserId = string
type User = {id: UserId, active: bool}
enum State { Draft, Ready, Complete }

An enum declares a closed set of no-payload variants. Values are constructed only through qualified access such as State.Ready. Enum values support equality, interpolation, JSON formatting, and exhaustive match.

9.2 Tool declarations

tool Files {
    read(path: string): string -> fs.read(path)
    count(paths: string[]): number -> {
        var n = 0
        for (var path in paths) { if (path.ends_with(".go")) n += 1 }
        return n
    }
}

A tool is a named method namespace. A method has positional parameters, optional type annotations, optional defaults, and either an expression body or a statement block. A method invocation creates a fresh call environment containing its parameters and does not expose caller-local variables. A declared return type is checked after evaluation. A block without return yields null.

9.3 Prompt declarations

prompt Review(file: string, language: string = "English") {
    "Review ${file}. Write the findings in ${language}."
}
prompt External(file: string) from "review.prompt.md"

A prompt is a named template. Prompt calls bind by parameter name, and missing parameters MUST have defaults or the call raises. Extra and unknown arguments raise. A default expression is evaluated in the caller scope for prompt calls; a prompt default MAY appear in any parameter position. An external Markdown body uses the same ${name} interpolation syntax; write \${name} when a literal placeholder must remain.

9.4 Extension declarations

extension mcp Issues {
    transport: "http"
    url: "https://mcp.example.test"
    headers: {"Authorization": "Bearer " + env("ISSUES_TOKEN")}
}

The generic form is extension kind Name { properties }. The kind selects a built-in or installed adapter. Properties are evaluated and validated by the adapter, which also defines the callable methods.

10. Standard library

11. Native operations

Native namespaces are reserved and can be called from pipeline statements, tool methods, hooks, and other expression positions. They execute host effects and therefore MUST be treated as privileged operations.

11.1 Command execution: cmd

SignatureSemantics
cmd.exec(command: string | string[], timeout?: duration) → {stdout: string, stderr: string, exit_code: number}A string is split on whitespace without shell quoting or expansion. An argv array passes every element verbatim. Non-zero exit is returned as exit_code; launch failure or timeout raises.
cmd.exec_all(commands: (string | string[])[], timeout?: duration) → object[]Runs commands concurrently, applies timeout per command, and returns results in input order. A launch failure raises; non-zero exits remain values.

11.2 Filesystem: fs

11.3 Git: git

12. Agents and traffic control

An agent declaration creates a callable single-shot backend. The call form is Name.run(prompt: ...); the prompt MUST be non-empty. An optional schema: argument is a string and is passed to backends that support structured output.

12.1 CLI and Ollama profiles

agent Reviewer {
    engine: "cli/claude-code"
    command: "claude"
    args: ["-p", "${prompt}", "--output-format", "json"]
    log: "logs/reviewer.${context.session_id}.log"
}
agent LocalModel {
    engine: "ollama/qwen2.5-coder"
    endpoint: "http://localhost:11434"
    temperature: 0.1
}

If engine is absent or begins with cli/, the runtime uses command and optional args. Each array element is one process argument; ${prompt} and ${schema} placeholders are injected without shell splitting. If engine begins with ollama/, the suffix is the model name and endpoint is required.

12.2 Hooks, fallbacks, retry, cache, and rate limits

PropertyContract
beforeA zero-parameter lambda. Its returned object contributes bindings to prompt and schema interpolation. It may call tools, extensions, agents, native operations, and memory.
afterA zero-parameter lambda with the final response bound as result. A returned string replaces the response; no return passes it through.
fallbackArray of declared agent names or inline agent objects. Each is tried after the previous leg fails; a successful fallback still invokes the primary agent's after hook.
retry{max_attempts, delay, retry_on, backoff}. The only backoff value currently supported is "exponential". Absent retry runs once.
cache{ttl, storage, strategy}. Cache keys include engine, prompt, and schema. The only strategy currently supported is exact matching; storage: "disk" persists it.
rate_limit{requests_per_minute, concurrency, on_exceeded}. Exceeded work queues; the supported value is "queue".
traceWhen true, emits call/response trace lines. Sensitive values remain subject to redaction.

Agent errors are eligible for retry according to retry_on, then fallbacks are attempted. A cache hit bypasses the external call and retry path. Agent log paths interpolate like strings and append raw CLI stdout; the log property is ignored for spawned calls, whose output is buffered and merged by the step.

13. Memory and state

13.1 Named memory declarations

13.2 Persistent pipeline variables

loop pipeline Poll {
    mem attempts = 0
    mem status = "pending"
    repeat: { stop_when: status == "done", max_iterations: 10 }
    step Check {
        attempts = attempts + 1
        status = if (attempts >= 3) "done" else "pending"
    }
}

mem name = expression is get-or-initialize. Its initializer runs only when no value exists. A mem variable survives loop iterations and is visible to repeat.stop_when. name.reset() deletes it. Pipeline-level var values are initialized once per ordinary run but reset between iterations of a loop pipeline.

14. Extensions

14.1 MCP client

extension mcp Name { ... } connects to a Model Context Protocol server over stdio or HTTP. The methods are:

SignatureSemantics
Name.call(tool: string, arguments?: object) → anyIssues tools/call and returns the decoded result. An input-required response raises because this client cannot elicit and resubmit input.
Name.list_tools() → anyIssues tools/list.
Name.discover() → anyIssues server/discover, or returns initialize identity for handshake-only servers.

The protocol property accepts auto (default), 2026-07-28 stateless, 2025-11-25, or 2025-06-18 handshake mode. In auto mode the stateless attempt is tried first and protocol incompatibility may trigger handshake fallback. Stdio calls create a fresh process; HTTP calls are independent requests. Credentials in headers SHOULD be obtained through env.

14.2 A2A client

extension a2a Name { url, headers, poll_interval?, poll_timeout? } connects to a remote Agent2Agent endpoint.

SignatureSemantics
Name.send(message: string, context?: string) → objectIssues message/send. A non-terminal task is polled with tasks/get. Message results are normalized to {kind, text, parts, message_id, context_id}; tasks include id, state, artifacts, history, and status.
Name.agent_card() → objectGETs /.well-known/agent-card.json from the endpoint origin.
Name.get_task(id: string, history_length?: number) → objectIssues tasks/get.
Name.cancel(id: string) → objectIssues tasks/cancel.

Streaming, push notifications, and input-required task continuation are not implemented in the current client profile.

14.3 External adapters

An unknown extension kind resolves through an installed external adapter. The adapter is an executable described by extension.json, selected by a locked identifier and SHA-256 digest, and spoken to over newline-delimited JSON-RPC. The host sends initialize, call, and shutdown; the adapter MAY send log and secret.resolve requests. Protocol messages belong on stdout; diagnostics belong on stderr.

{
  "id": "com.acme.crm",
  "api_version": "1",
  "executable": "bin/crm",
  "declarations": [{"kind": "crm", "methods": [{"name": "lookup"}]}]
}

Use mhl extension init, test, package, install, list, and doctor to create, probe, lock, and inspect adapters.

15. Pipelines and workflows

A pipeline is the executable unit. Inputs are supplied by the CLI or a server adapter and are validated against their declared types. Pipeline-level variables are shared across steps; step-local variables are not visible to later steps or repeat.stop_when.

15.1 Ordered execution and checkpoints

workflow Release {
    input environment: string
    var approved = false
    description: "Validate and publish a release"
    checkpoint: { enabled: true, strategy: "per_step", storage: "file", ttl: 7d }

    step Validate timeout 2m {
        var test = cmd.exec(["go", "test", "./..."], timeout: 90s)
        if (test.exit_code != 0) fail(test.stderr)
        approved = true
    }
    step Publish {
        if (!approved) goto Validate
        log.info("publishing to", environment)
    }
}

A plain pipeline runs steps in declaration order and rejects goto. A workflow has the same model but permits forward or backward jumps to its own named steps. A step timeout creates a deadline for blocking calls and fails the step when it expires. A checkpoint is saved after each completed step when per-step checkpointing is enabled; mhl run ... --resume re-enters after the last completed unit with a fresh timeout budget.

15.2 Loop pipelines

Prefix either form with loop and add repeat: {stop_when, max_iterations}. An iteration runs to completion before stop_when is evaluated. break wins over the stop condition and maximum. An error is not a soft stop: it aborts the run. A loop checkpoint records the next iteration and terminal reason (stop_when, max_iterations, break, or pause); a paused loop is re-entered by --resume, the others are not.

15.3 Context

pipeline Build {
    checkpoint: {enabled: true, strategy: "per_step"}
    context: {source: "latest", require: false}
    step Report {
        log(context.session_id, context.resumed)
        if (context.vars.keys().contains("build")) log(context.vars["build"])
    }
}

A declared context exposes the read-only object {session_id, started_at, resumed, principal, vars}. vars is the previous completed run's final variable state; principal is the verified server caller identity when available and is not an authorization mechanism. Context access is absent when the pipeline does not declare the block.

15.4 Parallel groups and spawned agents

pipeline Review {
    input diff: string
    spawn: {max_concurrency: 4}
    step Analyze {
        spawn code = Code.run(prompt: diff)
        spawn security = Security.run(prompt: diff)
        wait code, security timeout: 90s
        log(code.result, security.result)
    }
    parallel Gather timeout 2m {
        step Docs { docs = DocsAgent.run(prompt: diff) }
        step Issues { issues = IssuesAgent.run(prompt: diff) }
    }
}

spawn is valid directly inside a step and only accepts an Agent.run(...) call. It returns a task handle with result, ok, error, status, and duration_ms. wait names waits for all and fails fast; wait any names returns on the first success; wait N of names returns after N successes. The optional timeout: bounds the wait, and on_error: "collect" keeps errors inspectable rather than failing the step. Unjoined handles are drained at step end and cannot outlive a checkpoint.

A named parallel group is a barrier: all branches run concurrently and the pipeline advances only after all complete. Each branch receives a copy of shared pipeline variables; conflicting writes fail. Output is merged in declaration order. A group timeout cancels unfinished branches. goto cannot target or appear within a group, and break is not permitted in one.

16. Tests

A test declaration contains named describe blocks. Each description gets a fresh environment and supports the same statement grammar as a pipeline step. Assertion calls are recognized only inside descriptions.

test TextExamples {
    describe normalization {
        are_equal(" Feature ".trim().to_lower(), "feature")
        is_true([1, 2].contains(2))
        is_false([1, 2].contains(3))
    }
    describe future_case {
        incomplete("implementation pending")
    }
}
AssertionSignature / pass condition
are_equalare_equal(actual: any, expected: any)
are_not_equal / not_equalare_not_equal(a: any, b: any)
is_true, is_false(value: bool)
is_null, not_null(value: any)
greater_than, less_than(a: number, b: number)
greater_than_or_equal, less_than_or_equal(a: number, b: number)
includesincludes(array: any[], value: any)
incompleteincomplete(reason?: any)

Equality is deep and structural. Wrong assertion arity or type is a hard error. A failed assertion marks the description as failed; incomplete marks it pending and does not count as a failure.

18. Security and operational semantics

MHL programs can execute processes, modify files, access networks, call remote tools, and persist state. An implementation and operator SHOULD treat every .mh file as executable code.

  • Credentials SHOULD be referenced with env("NAME") and MUST NOT be embedded in source, command arguments, or committed state.
  • Arguments passed as argv arrays preserve boundaries and avoid accidental shell interpolation. Command strings SHOULD be reserved for deliberate shell-like behavior.
  • Authorization, Cookie, bearer, basic-auth, and recognized secret values are registered and redacted as [REDACTED] in logs, diagnostics, and checkpoints.
  • External adapters MUST be present in the extension lock and their executable digest MUST match before execution.
  • Timeouts, retry limits, concurrency limits, and loop ceilings SHOULD be configured for every external or potentially unbounded operation.
  • Checkpoint and memory paths SHOULD be scoped by session when concurrent runs must not share state.
  • Server mode SHOULD bind to loopback unless a token and an appropriate network boundary are configured. A token is a shared trust-domain secret, not per-user authorization.
Secrets and source controlDo not commit API keys, tokens, resolved credentials, log files, cache contents, or checkpoint state. Review extension permissions and the capabilities available to a process before running untrusted automation.

Annex B — Complete example

The following program demonstrates declarations, a prompt, typed input, persistent loop state, tools, an agent, native operations, and self-verification.

enum Outcome { Pending, Passed, Failed }
type Finding = {code: string, severity: string}

agent Reviewer {
    engine: "cli/reviewer"
    command: "reviewer"
    args: ["--prompt", "${prompt}"]
    retry: {max_attempts: 2, delay: 1s, backoff: "exponential"}
    rate_limit: {requests_per_minute: 10, concurrency: 2}
}

prompt Audit(repo: string, diff: string) {
    "Review ${repo}. Return JSON findings for this diff:\n${diff}"
}

tool Project {
    diff(dir: string = "."): string -> git.diff(dir: dir)
    verify(dir: string = ".") -> cmd.exec(["go", "test", "./..."], timeout: 2m)
}

loop workflow AuditLoop {
    input repo: string
    mem status = Outcome.Pending
    mem attempts = 0
    repeat: {stop_when: status == Outcome.Passed, max_iterations: 3}

    step Inspect {
        attempts = attempts + 1
        var diff = Project.diff(repo)
        var result = Reviewer.run(prompt: Audit(repo, diff))
        fs.write("audit.json", result)
        status = Outcome.Passed
    }
}

test AuditExamples {
    describe values {
        are_equal(type_of(Outcome.Passed), "enum")
        is_true([1, 2, 3].contains(2))
    }
}

Run it with mhl lint audit.mh, mhl test audit.mh, and mhl run audit.mh --input repo=.. The external reviewer executable must be available in the host environment.

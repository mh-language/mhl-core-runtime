AI workflows you can read, test and audit.

MHL is a small executable language for orchestrating agents, prompts, tools, memory and external services. Your program owns the flow; AI contributes judgment where it helps.

01 · WHY IT EXISTS

Prompt glue is not architecture.

The same logic written as an imperative script with model calls sprinkled through it, versus written as MHL declarations. Same outcome; only one of them can be reviewed, tested and explained to an auditor.

Without a language implicit 
risk = call_model(
  f"Classify the risk...\n{diff}",
  retries=3,            # policy buried in code
  timeout=45,
)
if "high" in risk.lower():   # parsing prose
    requests.post(HOOK, json={"risk": risk})
# where is the audit trail?
# what did run #482 actually do?
# can a reviewer read this as a process?
With MHL explicit 
step Classify {
    var risk = Reviewer.run(
        prompt: Triage(diff: diff)
    )
    Audit.append({ risk: risk, at: now() })
}

step Escalate {
    if risk == "high" {
        Hooks.notify(risk: risk)
    }
}
Policy is a declaration

retry, timeout, cache and fallback live on the agent, not scattered through logic.

Prompts are typed

Explicit signatures and composition, so lint catches the mistake before the run.

State is named

memory says what survives the next step, and where it is written down.

02 · ANATOMY OF A WORKFLOW

Read one MHL file, top to bottom.

A real pull-request reviewer in 39 lines. Walk the steps — the file highlights the part being explained.

review.mh 
import "std/http" as http

agent Reviewer {
    command: "claude"
    args: ["-p", "${prompt}"]
    timeout: 45s
    retry: 2
    cache: true
}

prompt Triage(diff: string) {
    """
    Classify the risk of this change.
    Answer with low, medium or high.

    ${diff}
    """
}

memory Audit {
    kind: "append"
    path: ".mhl/audit.jsonl"
}

pipeline ReviewPullRequest {
    input diff: string
    output risk: string

    step Classify {
        var risk = Reviewer.run(prompt: Triage(diff: diff))
        Audit.append({ risk: risk, at: now() })
    }

    step Escalate {
        if risk == "high" {
            http.post("https://hooks.example.com/review", { risk: risk })
        }
    }
}

03 · DETERMINISM AND AUDIT

If you can't explain the run, you can't ship it.

The runtime executes the flow you wrote and reports every step: policy applied, cache, retries, duration and the value that came out. Loops are bounded; long runs can checkpoint and resume.

TERMINAL
$ mhl run review.mh --input diff=@patch.diff

  ├ retry 0/2     tokens 1420 → 38
  └ risk = "high"
▸ step Escalate   http.post        200 OK       121ms
✔ ReviewPullRequest                             2.09s
  audit .mhl/audit.jsonl  +1 entry
  checkpoint .mhl/state/review-482.json
loop Refine max: 3 {
    var review = Reviewer.run(prompt: Critique(draft: draft))
    if review.score >= 0.9 { break }
    draft = Editor.run(prompt: Revise(draft: draft, notes: review))
}
Bound required every loop declares max — no runaway runs.
Executable tests describe and test run under mhl test.
Resume pause hands control to a human and continues later.

04 · INTEGRATIONS

Your workflows as MCP tools or A2A skills.

Point the runtime at a directory and every workflow is published with its input and output contract. One workflow, one tool.

MCP · STDIO

Local client

Newline-delimited JSON-RPC over a subprocess. The client spawns the process.

mhl serve mcp sample/serve
MCP · HTTP

Networked client

The same workflows over Streamable HTTP, with sessions and async runs.

mhl serve mcp --http \
  --addr 127.0.0.1:8711 sample/serve
A2A · HTTP

Agent interop

Publishes workflows as Agent2Agent tasks, with an Agent Card and task lifecycle.

mhl serve a2a \
  --addr 127.0.0.1:8710 sample/serve
!
Before exposing a server

Bind deliberately, configure authentication for non-local use, choose a state directory for resumable runs, and review the permissions of every workflow.

05 · START IN 30 SECONDS

From an empty folder to a running pipeline.

Install the runtime, save the example as hello.mh and run it. The echo agent needs no API key and no network.

macOS / Linux 
curl -fsSL https://raw.githubusercontent.com/mh-language/mhl-core-runtime/main/install.sh | sh
Windows / PowerShell 
irm https://raw.githubusercontent.com/mh-language/mhl-core-runtime/main/install.ps1 | iex
run mhl run hello.mh --input name=Ana
check mhl lint hello.mh mhl test hello.mh
output Hello, Ana. Your first pipeline is running.
hello.mh 
agent Echo {
    command: "echo"
    args: ["${prompt}"]
}

prompt Greeting(name: string) {
    "Hello, ${name}. Your first pipeline is running."
}

pipeline Hello {
    input name: string

    step Greet {
        var answer = Echo.run(prompt: Greeting(name: name))
        log(answer)
    }
}

01Programs and modules

Executable

A program is a sequence of top-level declarations. Use export to publish a declaration and use to import it from another file, optionally under a local alias.

TWO-FILE EXAMPLE

shared.mh
export agent Echo {
    command: "echo"
    args: ["${prompt}"]
}

export prompt Greeting(name: string) {
    "Hello, ${name}!"
}
main.mh
use {Echo, Greeting as Hello}
    from "shared.mh"

pipeline Welcome {
    input name: string
    step Run {
        log(Echo.run(
            prompt: Hello(name: name)
        ))
    }
}
FormSyntaxWhen to use it
Exportexport prompt Name(...) { ... }Make a declaration reusable.
Import namesuse {A, B} from "file.mh"Bring in explicit contracts only.
Local aliasuse {LongName as Short} from "file.mh"Avoid collisions and improve readability.
ALPHA

Prefer use for executable composition. The import "file.mh" as alias form is part of the syntax, but qualified namespace access is not yet the recommended operational form.

PRACTICAL GRAMMAR

03Expressions and collections

Executable

Expressions produce values. They compose inside variables, arguments, properties, conditions, returns, and string interpolation.

PRECEDENCE — LOWEST TO HIGHEST

??→||→&&→== !=→< > <= >=→+ -→* / %→! -→. ?. () []
var ready = retries < 3 && files.size() > 0
var label = if (ready) "ready" else "blocked"
var total = price * quantity + shipping
var dynamic = record[field_name]
var slice = numbers[1..^1] // index 1 through one before the end
var text = "${label}: ${total}"

// `?.` reads through null, a non-object, or a missing field without raising;
// `?.[key]` is the same with a dynamic key; `??` supplies a default only
// when the left side is null.
var target = metric?.target?.trim() ?? ""
var retries = config?.retries ?? 3       // 0 stays 0 — only null is replaced
var field  = record?.[name] ?? null      // no `is_object(record)` guard needed

VALUE METHODS

Common

size()is_empty()equals()deep_equal()

Strings, arrays, and objects. equals works on any value.

String

split()replace()contains()starts_with()ends_with()trim()to_upper()to_lower()substring()

Array

get_index()index_of()contains()filter()find()sort_by()map()reduce()any()all()append()join()unique()

Object

keys()values()get()

Keys are returned in stable order. get(key, default?) never raises on a missing field.

SIGNATURES

Every method's parameters, types, and return value are in the Standard Library.

RUNTIME TYPES

type_of(x) returns a kind string ("string", "number", "bool", "array", "object", "null", …); is_string, is_number, is_bool, is_array, is_object, is_null are the per-kind predicates. Pair them with ?. to branch on a dynamic field's shape.

DETERMINISTIC SELECTION EXAMPLE

var passed_ids = [10]
var features = [
    {id: 20, status: "pending", priority: 2, depends_on: [10]},
    {id: 30, status: "pending", priority: 1, depends_on: [99]},
    {id: 40, status: "pending", priority: 3, depends_on: []}
]

var ready = features
    .filter((f) -> f.status == "pending")
    .filter((f) -> f.depends_on
        .filter((d) -> !passed_ids.contains(d))
        .is_empty())
    .sort_by((f) -> f.priority)

var next = ready.find((f) -> f.id == 20)
IMMUTABLE RESULTS

filter(), map(), sort_by(), append(), unique(), concatenation, and slices return new arrays. To accumulate into a list, reassign — acc = acc.append(x) or acc += [x]. Assigning to items[index] or object[key] mutates the original collection.

    count_valid(items: {valid: bool}[]): number -> {
        var count = 0
        for (var item in items) {
            if (item.valid) count = count + 1
        }

pipeline SafeRead {
    step Read {
        try {
            var config = json.parse(fs.read("config.json"))

ERRORS

fail("message") creates a failure that catch can handle. Without a handler, the failure stops execution and the CLI returns a nonzero status.

05agent

Executable

Declares an AI backend callable through .run(prompt: ...). The runtime supports local CLI processes and models served by Ollama.

CLI AGENT

agent Claude {
    engine: "cli/claude-code"
    command: "claude"
    args: [
        "-p", "${prompt}",
        "--output-format", "json",
        "--json-schema", "${schema}"
    ]
    retry: {
        max_attempts: 3
        delay: 2s
        retry_on: [500, 503, "timeout", "rate_limit"]
    }
    cache: { ttl: 10m, storage: "disk" }
    rate_limit: { requests_per_minute: 20, concurrency: 2 }
}

OLLAMA AGENT AND CALL

agent LocalCoder {
    engine: "ollama/qwen2.5-coder"
    endpoint: "http://localhost:11434"
    temperature: 0.1
    fallback: [
        agent {
            command: "echo"
            args: ["fallback: ${prompt}"]
        }
    ]
}

var schema = """
{"type":"object","properties":{"summary":{"type":"string"}}}
"""
var raw = LocalCoder.run(
    prompt: "Summarize the change.",
    schema: schema
)
var result = json.parse(raw)

log"logs/run.${context.session_id}.log"cli/* engine: appends every call's raw stdout to this path. Interpolated for ${...} spans like a prompt string, so each run (or --session) can get its own file instead of concurrent runs interleaving into one. Ignored under spawn.

after(mcp, tools, result) -> {...}Runs once, on the final response.
!
Do not place secrets in args.

Prefer environment variables resolved by the invoked process. To preserve spaces and special characters in prompts, keep "${prompt}" as one complete array element.

BEFORE / AFTER HOOKS

An agent is a single-shot CLI process — it cannot decide mid-generation to call a tool or an MCP server. before/after are how the pipeline does that calling on the agent's behalf: real values, fetched before the prompt exists, not a hope the model reads and acts on an instruction.

agent Reviewer {
    command: "claude"
    args: ["-p", "${prompt}"]
    tools: [execution]
    mcp_servers: [GitHub]

    before: (mcp, tools) -> {
        return {
            issue: mcp.GitHub.call("get_issue", { number: 42 }),
            diff: tools.execution.git_diff()
        }
    }
    after: (mcp, tools, result) -> {
        log("review is ${result.size()} characters")
    }
}

var review = Reviewer.run(
    prompt: "Issue: ${issue}\nDiff: ${diff}\nWrite a review."
)
  • mcp/tools are maps keyed by declared name — mcp.GitHub, tools.execution — covering every entry in that agent's own mcp_servers:/tools:, not any other declaration in the program.
  • A dotted entry in tools: (tools: [execution.read_file]) narrows that tool's binding to just that method; calling any other method on it is rejected. Naming the same tool bare anywhere in the list removes the restriction.
  • before's returned object's fields become real "${...}" bindings available to that call's prompt:/schema: arguments.
  • after runs once, against whichever leg — the primary agent or a successful fallback — produced the final response. A non-null string return replaces that response; anything else (including no return) passes it through unchanged.
REAL VS. BEST-EFFORT

before/after execute real calls through mhl itself — the model never has to cooperate. tools:/mcp_servers:'s prompt text (above) is the opposite: a hint the model may or may not act on, since mhl has no channel to enforce it against a CLI-backed agent. Prefer before/after when the agent actually needs the data to do its job.

06prompt

Executable

A named template with parameters. A prompt renders to a string and can be passed to an agent or composed into another prompt.

INLINE AND COMPOSED

prompt Role() {
    "You are a software security reviewer."
}

prompt Review(role: prompt, file: string, code: string) {
    """
    ${role}

    Review ${file}. Return concrete risks and a minimal fix.

    ${code}
    """
}

var request = Review(
    role: Role(),
    file: "auth.go",
    code: fs.read("auth.go")
)

MARKDOWN BODY

review.prompt.md
# Review of ${file}

## Criteria
- correctness
- security
- compatibility

## Code
${code}
prompts.mh
prompt Review(
    file: string,
    code: string
) from "review.prompt.md"

var rendered = Review(
    file: "main.go",
    code: fs.read("main.go")

  • Missing, extra, or unknown placeholders fail instead of producing incomplete text.

07memory and mem

Executable

memory declares a named store. mem creates a pipeline-scoped persistent variable, ideal for a loop pipeline stop condition.

NAMED MEMORY

memory Session {
    type: "json"
    path: ".mhl/session.json"
}

memory Audit {
    type: "append_log"
    path: ".mhl/audit.log"
}

Session.set("attempt", 1)
Session.set({status: "running", owner: "platform"})
var attempt = Session.get("attempt", 0)
Session.remove("owner")
Audit.append("pipeline started")
TypeConfigurationOperations
In-memory KV{type: "kv", store: "memory"}set, get, remove; lasts one execution.
JSON{type: "json", path: "state.json"}set, get, remove; persists to disk.
Text log{type: "append_log", path: "audit.log"}append; one line per call.
JSONL{type: "append_jsonl", path: "events.jsonl"}append; one JSON object per line.
PATHS

In JSON memory, Session.get("config::retry") navigates nested objects. remove("config::retry") removes only the targeted field.

PERSISTENT PIPELINE VARIABLE

loop pipeline Poll {
    mem attempts = 0
    mem status = "pending"

    repeat: {
        stop_when: status == "done"
        max_iterations: 10
    }

    step Check {
        attempts = attempts + 1
        status = if (attempts >= 3) "done" else "pending"
        log.info("attempt", attempts, status)
    }
}
  • mem name = value uses get-or-init semantics: the initializer runs only when no value exists.
  • The value survives between iterations and is visible to repeat.stop_when.
  • name.reset() deletes the persisted value; the next access initializes it again.

08tool and native operations

Executable

A tool creates a small, reusable API over native operations. Methods take positional arguments, may declare types, and use either an expression body or a statement block.

tool Project {
    read(path: string): string -> fs.read(path)

    test(package: string): {stdout: string, stderr: string, exit_code: number} ->
        cmd.exec(["go", "test", package], timeout: 2m)

    changed_go_files(): string[] -> {
        var paths = fs.list(".")
        return paths.filter((path) -> path.ends_with(".go"))
    }
}

var source = Project.read("main.go")
var result = Project.test("./...")
if (result.exit_code != 0) fail(result.stderr)

SIGNATURES

Full parameter names, types, and return shapes for every native operation are in the Standard Library.

var result = cmd.exec(["git", "status", "--short"], timeout: 30s)
var response = http.post(
    url: "https://api.example.com/jobs",
    headers: {"Authorization": "Bearer " + env("API_TOKEN")},
    body: {status: "ready"}
)
var jobs = http.get(
    url: "https://api.example.com/jobs",
    query: {"state": "ready", "limit": "50"},
    tls: {cert: "client.pem", key: "client.key"},   // mutual TLS
    proxy: "http://corp-proxy:3128"                  // else HTTP(S)_PROXY is used
)
if (jobs.ok) fs.write("result.json", json.stringify(jobs.json))
http.download("https://api.example.com/artifacts/build.zip", "build.zip")
var expires_at = time.add(time.now(), 7d)

time.parse/time.format's layout accepts either a raw Go reference-time layout ("2006-01-02") or the friendlier yyyy/MM/dd/HH/mm/ss tokens (e.g. time.format(dt, "dd/MM/yyyy")) — case matters where a unit would otherwise be ambiguous: MM is always month, mm is always minute; HH is always 24-hour, hh is always 12-hour.

var target = input.repo_dir                       // some checkout, not this one

if (git.status(dir: target).exit_code != 0) fail("${target} is not a git repository")

var diff = git.diff("HEAD", dir: target)
if (!diff.is_empty()) {
    git.add(["src/", ":(exclude).harness"], dir: target)
    var committed = git.commit("chore: sync generated files", dir: target)
    if (committed.exit_code != 0) fail(committed.stderr)
}
var sha = git.rev_parse("HEAD", dir: target)      // short hash, e.g. "0661a80"
var recent = git.log(5, dir: target)             // --oneline text, newest first

git operations run git in the interpreter's working directory — or in a dir: argument when given (every git.* op accepts one; it maps to git -C <dir>), so a pipeline can act on a checkout other than its own. status, add and commit return the same inspectable {stdout, stderr, exit_code} shape as cmd.exec — a non-zero exit is a value to check, not a raised error — while diff, log and rev_parse return plain text and fail closed, raising on a bad ref. add requires at least one path, commit a non-empty message, log a positive count, and rev_parse a non-empty ref; each is validated before git is invoked. commit's message is passed as its own argument, never shell-quoted, so spaces survive intact; diff takes an optional target ref, and status/commit an optional trailing paths filter.

!
Prefer argv.

cmd.exec(["program", "arg with spaces"]) preserves every argument and avoids accidental shell interpolation. Use a command string only when shell features are actually required.

09mcp_server

Executable

Declares a Model Context Protocol server connection. Configuration supports stdio or HTTP transports and secure environment references. Call it with Server.call("toolName", { ... }), discover its catalog with Server.list_tools(), or inspect it with Server.discover().

stdio

mcp_server LocalFiles {
    transport: "stdio"
    command: "npx"
    args: [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "."
    ]
}

HTTP

mcp_server IssueTracker {
    transport: "http"
    url: "https://mcp.example.com"
    headers: {
        "Authorization":
            "Bearer " + env("MCP_TOKEN")
    }
}

var result = IssueTracker.call("search_issues", { query: "is:open" })
var catalog = IssueTracker.list_tools()
var info = IssueTracker.discover()
  • transport: "stdio" uses command and args; each call spawns a fresh process.
  • transport: "http" uses url and headers; each call is a fresh, independent request.
  • env("NAME") resolves a credential only when needed and keeps it out of source.
  • .call(toolName, arguments) issues a JSON-RPC tools/call; .list_tools() issues tools/list; .discover() issues server/discover (supported versions/capabilities/identity), or, against a handshake server, returns the initialize result's identity instead.
  • protocol: selects the wire protocol: "auto" (default), "2026-07-28" (stateless only), "2025-11-25" or "2025-06-18" (standard handshake, advertising that revision). Any other value is a build-time error.
  • In "auto" mode the stateless 2026-07-28 form is tried first; if the server rejects it with a protocol-incompatibility error (JSON-RPC -32602/-32600, or HTTP 400) the call is retried over the standard initialize / notifications/initialized handshake (advertising 2025-11-25, _meta dropped, Mcp-Session-Id threaded through), letting the server negotiate the version down. If both fail, the error names both attempts.
  • On http, .call(...) first checks the target tool's schema for x-mcp-header-annotated arguments (top-level, string/integer/boolean only) and mirrors any present into Mcp-Param-{Name} headers — best-effort: if the schema can't be fetched, the call proceeds without them.
  • A server response with resultType: "input_required" (Multi Round-Trip Requests — the server wants elicitation/sampling input) is rejected with a clear error; this client cannot gather and resubmit that input.
PROTOCOL

A stateless 2026-07-28 call keeps no session between calls — each is fully independent, self-identifying with its protocol version, capabilities, and a {name: "mhl", version} clientInfo. "auto" (the default) may fall back to a short initialize/notifications/initialized handshake for a server on the 2025-11-25 or 2025-06-18 revisions; that handshake session lives only for the one call. A credential that fails to resolve aborts the call instead of sending a request with an empty header.

10a2a_agent

Executable

Declares a stateless connection to a remote agent that speaks the Agent2Agent (A2A) protocol, revision 0.2.x: JSON-RPC 2.0 over HTTP(S) with header-based auth. Send it a message with Agent.send("..."), read its published capabilities with Agent.agent_card(), and poll or abort a running task with Agent.get_task(id) / Agent.cancel(id).

Declaration

a2a_agent Translator {
    url: "https://translator.example.com/a2a"
    headers: {
        "Authorization":
            "Bearer " + env("A2A_TOKEN")
    }
    poll_interval: 1s     // optional, default 1s
    poll_timeout: 120s    // optional, default 120s
}

Use

var reply = Translator.send("Translate 'hello' to French")
log(reply.text)                       // -> "bonjour"

var card = Translator.agent_card()    // /.well-known/agent-card.json
var again = Translator.send("and to German?", context: reply.context_id)

var status = Translator.get_task(reply.task_id)
var stopped = Translator.cancel(reply.task_id)
  • url is the remote agent's JSON-RPC endpoint; headers carry auth, with env("NAME") resolving a credential only when needed and keeping it out of source.
  • .send(message, context?) issues message/send with the string as a single text part. If the reply is a Task that is not yet in a terminal state, it polls tasks/get every poll_interval until the task finishes or poll_timeout elapses. context: sets contextId for a follow-up turn.
  • The result is a normalized object: a message is {kind: "message", text, parts, message_id, context_id}; a task is {kind: "task", task_id, context_id, state, text, artifacts, history, status}. text is the concatenation of every text part — a convenience; the raw parts/artifacts are still there.
  • .agent_card() GETs <origin>/.well-known/agent-card.json. .get_task(id, history_length?) issues tasks/get; .cancel(id) issues tasks/cancel.
  • A task that stops in input-required or auth-required is rejected with a clear error — mhl's A2A client cannot gather and resubmit that input.
STATELESS

Every method is one or more independent requests with no session between them; a blocking .send that polls keeps no state beyond the task id. A credential that fails to resolve aborts the call before any request. Streaming (message/stream) and push notifications are not implemented yet.

11pipeline and loop pipeline

Executable

Pipelines are the executable unit. Inputs arrive through the CLI, pipeline variables are shared across steps, and steps run in order unless an explicit transition redirects them.

RECOVERABLE PIPELINE

pipeline Release {
    input environment: string
    var approved = false

    checkpoint: {
        enabled: true
        strategy: "per_step"
        storage: "file"
        ttl: 7d
    }

    step Validate {
        var result = cmd.exec(["go", "test", "./..."], timeout: 2m)
        if (result.exit_code != 0) fail(result.stderr)
        approved = true
    }

    step Publish {
        if (!approved) goto Validate
        log.info("publishing to", environment)
    }
}
startmhl run release.mh --input environment=staging
resumemhl run release.mh --input environment=staging --resume
pinmhl run release.mh --session nightly-42 --resume
SESSIONS

Every run gets its own directory .mhl/state/<session-id>/, so two concurrent runs of the same pipeline never clobber each other's checkpoint. Each run prints a session: <id> line; a bare --resume follows the most recent one (via a .mhl/state/<pipeline>.latest pointer), and --session <id> pins an exact one. Abandoned session directories past their TTL are swept automatically at the start of a later run.

READING THE PREVIOUS RUN'S STATE

pipeline BuildCounter {
    checkpoint: { enabled: true, strategy: "per_step", ttl: 7d }

    context: {
        source: "latest"     // or "session:<id>"; default "latest"
        require: false        // true = fail the run when no prior state exists
    }

    var build = 1

    step Report {
        log.info("session ${context.session_id}, resumed=${context.resumed}")
        if (context.vars.keys().contains("build")) {
            build = context.vars["build"] + 1
        }
    }
}
CONTEXT

context is read-only. context.session_id, context.started_at and context.resumed describe the current run; context.vars is the variable state the previous completed run of this pipeline finished with (persisted as result.json in that run's session directory). It is empty until a run has completed once — guard with context.vars.keys().contains(...).

LOOP WITH AN EXPLICIT STOP

loop pipeline PollBuild {
    mem status = "pending"
    mem checks = 0

    repeat: {
        stop_when: status == "passed"
        max_iterations: 20
    }

    step Check {
        checks = checks + 1
        var response = http.post(
            url: "https://ci.example.com/status",
            body: {attempt: checks}
        )
        status = json.parse(response.body).status
        if (status == "failed") break "build failed"
    }
}

CONCURRENT SUB-AGENTS IN A STEP

pipeline Review {
    input diff: string

    spawn: { max_concurrency: 4 }   // run-wide ceiling; default 4

    step Analyze {
        spawn rev   = Reviewer.run(prompt: "review:\n${diff}")
        spawn tests = Tester.run(prompt: "run the tests for:\n${diff}")
        spawn sec   = Security.run(prompt: "security pass:\n${diff}")

        wait rev, tests, sec timeout: 90s        // wait-all, fail-fast
        // wait any rev, tests, sec              // first success, cancels the rest
        // wait 2 of rev, tests, sec             // first N successes (quorum)
        // wait rev, tests on_error: "collect"   // never fails the step; read .ok / .error

        log(rev.result)
        if (!tests.ok) log("tests failed: ${tests.error}")
    }
}

LIMITS

For loops, always prefer an observable stop_when plus max_iterations as a safety ceiling. Step-local variables are not visible to stop_when; use mem or memory.

SPAWN

spawn/wait are step-scoped: any handle not joined by a wait is joined automatically when the step ends, so nothing runs across a checkpoint. If the process dies mid-step, --resume re-runs the whole step and re-issues every spawn — keep them idempotent (or give the agent a cache). A spawned agent cannot itself spawn, and an agent's log: file is ignored under spawn (its output goes to the step log instead).

12test and describe

Executable

MHL files can be self-verifying examples. Each describe receives a fresh environment and uses the same statement syntax as a step.

tool Normalize {
    slug(text: string): string ->
        text.trim().to_lower().replace(" ", "_")
}

test normalize_examples {
    describe basic_slug {
        are_equal(Normalize.slug(" Feature Title "), "feature_title")
    }

    describe array_selection {
        var values = [1, 2, 3, 4]
        var even = values.filter((n) -> n % 2 == 0)
        are_equal(even, [2, 4])
        is_true(even.contains(4))
        is_false(even.contains(3))
    }

    describe future_behavior {
        incomplete("waiting for implementation")
    }
}

!
Principle of least privilege

A pipeline can run processes, write files, and access the network. Treat .mh files as code: review them before execution, limit available credentials, and run untrusted automation in an isolated environment.

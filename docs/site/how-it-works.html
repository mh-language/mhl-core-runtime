02 · FROM FILE TO RESULT

What happens when you run mhl run?

The runtime turns a readable workflow into a bounded execution. Every step has a place in the sequence, and every external effect can be inspected as part of the run.

1

Load the program

Parse the `.mh` file, resolve imports, and validate declarations and types.

mhl lint workflow.mh
2

Prepare the run

Read pipeline inputs, initialize memory, and restore a checkpoint when resuming.

mhl run workflow.mh --input id=42
3

Execute each step

Evaluate expressions, call tools or agents, apply retries and timeouts, and record results.

step Analyze { ... }
4

Persist and finish

Write logs and state, stop when the pipeline succeeds or reaches an explicit limit, and return an outcome.

mhl test workflow.mh

04 · A CONCRETE EXAMPLE

AI where it helps. Code where it counts.

This small repair loop runs a test first. Only a failed test calls the agent; the harness keeps the diff, retry count, and stop condition explicit.

agent Fixer {
    engine: "ollama/qwen2.5-coder"
    endpoint: "http://localhost:11434"
    temperature: 0.1
}

tool Project {
    test() -> cmd.exec(["go", "test", "./..."])
    diff() -> git.diff()
}

prompt Repair(failure: string, diff: string) {
    "Fix this test failure with the smallest safe change.\n${failure}\n${diff}"
}

loop pipeline AutoRepair {
    mem attempts = 0
    mem done = false
    repeat: { stop_when: done, max_iterations: 5 }

    step Verify {
        var result = Project.test()
        if (result.exit_code == 0) {
            done = true
        } else {
            attempts = attempts + 1
            var patch = Fixer.run(prompt: Repair(
                failure: result.stderr,
                diff: Project.diff()
            ))
            fs.write("candidate.patch", patch)
        }
    }
}
1

Verify with a deterministic command.

2

Ask the agent only after failure.

3

Persist the proposed patch for review.

4

Stop on success or the iteration ceiling.

05 · THE PAYOFF

Make the workflow easier to trust.

MHL is useful when an AI-assisted process needs the same qualities as other engineering systems: visible boundaries, repeatable control, and a record of what happened.

01

Predictable control

Steps, branches, retries, timeouts, and iteration limits are written beside the flow.

02

Replaceable intelligence

Change the agent declaration or engine without rewriting the pipeline's intent.

03

Recoverable state

Memory and checkpoints make long-running or interrupted work visible and resumable.

04

Auditable effects

Tools, extensions, logs, and tests show what the workflow touched and why it stopped.

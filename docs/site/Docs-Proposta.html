Hoje, squads desenvolvem integrações com IA utilizando scripts Python imperativos dispersos (LangChain, orquestradores caseiros). No ambiente bancário, essa abordagem gera três graves passivos:

Opacidade Regulatória (Risco Bacen)

Decisões tomadas em caixas-pretas estocásticas sem rastreabilidade determinística de passos e prompts.

Dispersão de Custos e Loops Descontrolados

Tokens expostos em strings e acoplamento severo a APIs proprietárias de um único provedor.

02 · A Solução Técnica • MHL (Meta-Harness Language)
Slide 3 / 7

O programa detém o controle; a IA provê o julgamento.

A MHL é uma DSL declarativa construída especificamente para orquestrar agentes com garantias estritas de engenharia de software:

01

Passos Determinísticos

Blocos `step`, grupos `parallel` com barreira e laços com `max_iterations` obrigatório. O modelo nunca dita o fluxo.

02

Human-in-the-Loop

Primitiva nativa `pause()` suspende o processo de forma limpa e aguarda decisão humana com `run/resume` sem perder estado.

03

Checkpoints & Resume

Persistência automática `per_step`. Se a rede ou LLM falhar, a esteira retoma com `mhl run --resume` exatamente de onde parou.

04

Segurança & Vault

Resolução de credenciais via `env()` com ofuscação `[REDACTED]` automática em logs e execução pura via argv isolado.

review_pipeline.mh (Declarativo MHL) Auditável & Resiliente 
agent Reviewer { command: "claude", cache: { ttl: 1h }, retry: { max_attempts: 2 } }

workflow ValidacaoDeploy {
    input diff: string
    step Analisar { var risco = Reviewer.run(prompt: Classifica(diff: diff)) }
    step GateSeguranca {
        if (risco == "alto") { pause("Aguardando alçada do Tech Lead") }
    }
}

03 · Padrões Globais • Interoperabilidade Corporativa
Slide 4 / 7

Pronto para os padrões abertos que lideram o mercado.

A MHL opera nativamente nos dois protocolos abertos mais relevantes da indústria de IA corporativa, atuando tanto como cliente quanto como servidor:

MCP

Model Context Protocol

Padrão Anthropic adotado pela indústria

stdio + HTTP

Conecte qualquer base de dados ou API interna do Itaú via MCP (`extension mcp`). Ou exponha pastas de workflows MHL inteiras como ferramentas MCP para Claude Desktop, Cursor ou agentes corporativos com um único comando:

$ mhl serve mcp --http esteiras/
A2A

Agent2Agent Protocol

Padrão Google para colaboração entre agentes

JSON-RPC HTTP

Permite que diferentes agentes especializados colaborem sem atrito. O runtime publica automaticamente o `agent-card.json` e gerencia tarefas longas, cancelamentos e ciclo de vida:

$ mhl serve a2a --addr 0.0.0.0:8710 esteiras/
Benefício para o Itaú: Workflows construídos hoje podem ser reaproveitados amanhã por qualquer novo agente ou modelo sem reescrever código.

Matriz Técnica: Frameworks Convencionais vs. MHL Corporativa no EKS

Requisito Corporativo Itaú Scripts Python / Frameworks Tradicionais Padrão MHL no EKS
Escalabilidade Horizontal (Multi-Pod) Acoplamento à memória do pod; se o nó morrer ou o HPA rotacionar, a execução é abortada. Estado e sessões desacoplados em store compartilhado (S3/Aurora); retoma em qualquer pod.
Isolamento de Dados Multi-Tenant Geralmente requer uma instância/deploy isolado por squad, inflando custos operacionais. Multi-tenant nativo por --principal-header: mesmo cluster atende dezenas de squads com partições seguras.
Gates de Alçada Humana (HITL) Exige criar tabelas customizadas, filas RabbitMQ/Kafka e APIs REST manuais de webhook. Primitiva pause() nativa: suspende o processo e aguarda run/resume sem custo de computação ociosa.
Auditoria Bacen e Rastreabilidade Logs dispersos em stderr sem amarração de sessão, prompt exato e respostas intermediárias. Trilha append-only (`.mhl/audit.jsonl`), checkpoints imutáveis e conformidade com Resolução Bacen 85.

Roteiro Operacional da Prova de Conceito (PoC)

Cronograma de 4 semanas com escopo delimitado, baixo esforço e critérios binários de Go / No-Go

Investimento de Risco Zero
S1

Semana 1: Preparação e Segurança

Homologação
  • Disponibilização do binário `mhl` nos runners de homologação (sem impacto em produção).
  • Configuração da injeção de tokens via `env()` conectada ao cofre corporativo (Vault).
  • Validação das políticas de segurança estática com a equipe de Cyber Security do Itaú.
Entregável: Ambiente de testes validado e execução do primeiro teste de integração com sucesso.
S2

Semana 2: Codificação do Pipeline Piloto

Implementação
  • Construção do workflow de validação inteligente de Pull Requests em sintaxe MHL declarativa.
  • Implementação do gate humano com a primitiva `pause()` e retomada via `mhl_run_resume`.
  • Criação da suite de testes de conformidade com os blocos nativos `test` e `describe`.
Entregável: Pipeline de auditoria pronto para rodar com o squad voluntário.
S3

Semana 3: Shadow Run (200 PRs Reais)

Métricas
  • Execução em paralelo e silenciosa em 200 pull requests reais de microsserviços do banco.
  • Medição precisa de economia de tokens via cache de prompts e tempo de resposta da esteira.
  • Auditoria cega dos logs append-only pelo time de Governança de TI do Itaú.
Entregável: Relatório quantitativo comparando o processo manual vs esteira MHL.
S4

Semana 4: Apresentação e Decisão

Conclusão
  • Sessão de 30 minutos com a diretoria de tecnologia para apresentação dos resultados.
  • Comprovação da redução de custos e aderência estrita às normas do Bacen.
  • Definição de roadmap para adoção corporativa gradual no catálogo de arquitetura.
Entregável: Decisão executiva de homologação corporativa da MHL no Itaú.

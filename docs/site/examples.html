Choose the next step

The ArtifactKind enum defines the supported formats. An entry route chooses the first step from the input, and both paths end at Done.

entry route
Starts the workflow at the routing table.
goto
Jumps to a step whose name is checked by the linter.
complete()
Ends the workflow in the completed state.
Related playground lesson↗
mhworkflow.mh
enum ArtifactKind { Brief, Adr }

workflow CreateArtifact {
    description: "Choose a brief or an architecture decision record."

    input artifact: ArtifactKind = ArtifactKind.Brief

    entry route Generate(artifact: ArtifactKind) {
        ArtifactKind.Brief -> Brief
        ArtifactKind.Adr -> Adr
    }

    step Brief {
        log("brief ready")

        goto Done
    }

    step Adr {
        log("adr ready")

        goto Done
    }

    step Done {
        complete()
    }
}
$mhl run workflow.mh --input artifact=Brief
EXPECTED OUTPUTbrief ready

Limit the number of rounds

A loop pipeline repeats its steps in declaration order. This example uses mem to accumulate revisions and break to stop the run on the second round.

max 3
Sets a ceiling of three iterations.
mem
Retains values across iterations and resumes in the same session.
break
Ends the entire execution early.

To check a condition between rounds, use repeat with stop_when and max_iterations.

Related playground lesson↗
mhlimits.mh
loop pipeline RevisionRounds max 3 {
    description: "Run up to three local revision rounds."

    mem round = 0
    mem draft = "first draft"

    output: { rounds: round, text: draft }

    step Improve {
        self.round += 1
        self.draft = "${draft} / revision ${round}"
    }

    step Evaluate {
        log("round ${round}")

        if (round == 2) {
            break "ready"
        }
    }
}
$mhl run limits.mh
EXPECTED OUTPUTround 1 round 2

Send a list of items to agents

spawn … for starts one call per item. The runtime limits calls in flight and wait joins their handles. Echo stands in for a model so this example runs locally.

spawn … for
One task handle per collection item.
concurrency 2
At most two calls of this fan-out in flight at once.
wait
Wait for all tasks; any and N of select other policies.

wait any checks returns on the first success; wait 2 of checks waits for two successes. Both cancel remaining tasks: remove on_error: "collect" when using these policies. collect applies only to plain wait; inspect .ok and .error. Requires echo on PATH.

Related playground lesson↗
mhfanout.mh
agent Echo {
    command: "echo"
    args: ["${prompt}"]
}

pipeline ReviewFiles {
    description: "Check each file with up to two concurrent agent calls."

    step FanOut timeout 5s {
        const files = ["api.go", "auth.go", "cli.go"]

        spawn checks concurrency 2 = Echo.run(prompt: "check ${file}") for file in files
        wait checks timeout: 2s on_error: "collect"

        for (var check in checks) {
            if (check.ok) {
                log(check.result)
            } else {
                log.warn("Check ${check.status}:", check.error)
            }
        }
    }
}
$mhl run fanout.mh
EXPECTED OUTPUTcheck api.go check auth.go check cli.go

Run steps in parallel

Each branch writes to a group variable. Once both branches finish, merge combines their results into the summary that Report prints.

parallel
Runs whole steps in parallel.
timeout 2s
A deadline for the entire group.
merge
Combines branch results before the next step.
Related playground lesson↗
mhparallel.mh
pipeline Enrich {
    description: "Gather documentation and test status in parallel."

    var summary = ""

    output: { summary }

    parallel Gather timeout 2s {
        var docs = ""
        var tests = ""

        step Docs {
            self.docs = "docs ready"
        }

        step Tests {
            self.tests = "tests ready"
        }

        merge {
            self.summary = "${docs}; ${tests}"
        }
    }

    step Report {
        log(summary)
    }
}
$mhl run parallel.mh
EXPECTED OUTPUTdocs ready; tests ready

Pause for approval and resume

The run pauses for a boolean decision. In the same session, pass true to approve or false to reject. Each terminal step logs the outcome.

pause(…, decision: bool)
Saves the checkpoint and waits for a typed decision.
--resume --decision
Validates the answer and delivers it to the current gate.
goto match
Chooses the terminal step from the decision.

Resuming re-executes Gate from the start. Put external effects in their own steps and keep those effects safe to repeat.

Related playground lesson↗
mhapproval.mh
workflow Approval {
    description: "Wait for a decision and log the outcome."

    checkpoint: { ttl: 7d }

    step Gate {
        /// true approves the proposal, false rejects it.
        var approved = pause("Approve this proposal?", decision: bool)

        goto match approved {
            true -> Publish
            false -> Reject
        }
    }

    step Publish {
        log("approved")

        complete()
    }

    step Reject {
        log("rejected")

        complete()
    }
}
$mhl run approval.mh --session demo mhl run approval.mh --session demo --resume --decision true
EXPECTED BEHAVIORFirst run: paused After resume: approved

Define and test a contract

A typed signature defines inputs and results. The prompt renders the greeting, and output defines the public result. The test checks the terminal state, executed steps, and output.

GreetingInput / GreetingOutput
Input and output object types.
prompt
A reusable template with typed parameters.
test
Assertions about the local run's outcome.

The projected result is checked at completion. When served over MCP, the input and output types are advertised as schemas for clients.

Related playground lesson↗
mhcontract.mh
type GreetingInput = { name: string }
type GreetingOutput = { message: string }

prompt Greeting(name: string) {
    "Hello, ${name}!"
}

pipeline Greet(request: GreetingInput): GreetingOutput {
    description: "Render a greeting for the requested name."

    var message = ""

    output: { message }

    step Build {
        self.message = Greeting(name: request.name)
    }
}

test greeting {
    describe greets_by_name {
        var result = Greet.run(inputs: { name: "Ana" })

        are_equal(result.state, "completed")
        are_equal(result.executed, ["Build"])
        are_equal(result.output, { message: "Hello, Ana!" })
    }
}
$mhl run contract.mh --input name=Ana mhl test contract.mh

Refine a draft with an agent

The agent improves a draft and receives feedback from two reviews before the next round.

mhrefine.mh
agent Writer {
    command: env("MHL_WRITER_CMD", "claude")
    args: ["-p", "${prompt}"]
    timeout: 30s
    cache: { ttl: 10m, storage: "disk" }
}

prompt Revise(draft: string, feedback: string) {
    """
    Revise the draft using the review notes. Return only the revised draft.

    <draft>
    ${draft}
    </draft>

    <review_notes>
    ${feedback}
    </review_notes>
    """
}

prompt Review(draft: string, lens: string) {
    """
    Review the draft for ${lens}. Return concise, actionable feedback.

    <draft>
    ${draft}
    </draft>
    """
}

loop pipeline Refine max 3 {
    description: "Refine a draft over at most three rounds of parallel review."

    mem draft = "A first draft."
    mem feedback = ""

    output: { draft }

    step Improve timeout 45s {
        self.draft = Writer.run(prompt: Revise(draft: draft, feedback: feedback))
    }

    step Review timeout 45s {
        const lenses = ["clarity", "consistency"]

        spawn checks concurrency 2 = Writer.run(
            prompt: Review(draft: draft, lens: lens)
        ) for lens in lenses
        wait checks timeout: 40s

        self.feedback = checks.map((check) -> check.result).join("\n")
    }
}
$mhl run refine.mh --format json

The run uses an authenticated Claude CLI and caches responses locally for 10 minutes. Use --dry-run to inspect the plan or set MHL_WRITER_CMD to echo to exercise the flow locally.
